# AirCard WebClip 实验版

基于 Mak5er/AirCard-iOS。保留上游 MIT 许可证及作者署名。

新增 WebClip 页面只对 **iOS 27.0.1** 开放设备写入。构建成功不代表实机功能已验证。

## 安装

从 GitHub Actions 的 `AirCard-WebClip-unsigned-编号` artifact 下载 ZIP，解压得到 IPA。
这是未签名的设备版 IPA，需要用自己的有效签名方式安装。
应用名称为 **AirCard WebClip**，Bundle ID 为 `com.atttqj.aircard.webclip`，可与原版并存。
在本实验版内重新导入本机配对文件或完成配对，并按上游说明启用 LocalDevVPN。
配对文件留在手机上，不要上传到仓库、Actions 或 issue。

## 液态玻璃外观（1.3.3）

构建固定使用 Xcode 26.3 / iOS 26.2 SDK，原生标签栏、导航栏与弹窗由系统呈现新外观。
WebClip 主操作按钮在 iOS 26 及以上采用系统 `glassProminent` 样式；表单内容保持清晰实底。
模拟器测试明确选择 iOS 26 及以上，避免旧系统截图误判外观。IPA 校验同时检查 SDK 版本和旧设计兼容开关。
系统「降低透明度」等辅助功能可能改变材质效果。外观更新不代表设备写入已通过实机验证。

## 第二步搬运证据与报告刷新（1.3.9）

2026-10-29 收到 v3 实机报告：清单的三个条目全部接纳，第一步源链接消失，第二步源载荷仍存在，第三步取回未发送。用户确认手机已有 Safari 添加到主屏幕的网页图标。该报告没有给出权限拒绝，尚不能把第二步失败归因为安全限制或目录不存在。

v4 保持原有搬运顺序与停止条件，增加暂存链接元数据，以及搬运结束后的独立 AFC 只读查询：链接类型、链接目标和 `link/.` 元数据。查询使用独立连接并限制为 4 秒，超时不会复用该连接清理。AFC 查询失败不能证明真实目标目录不存在，也不能证明 ATC 被拒绝；原 2 秒源对象观察窗口仍属未验证条件。此版本未宣称修复实机写入。

目录验证期间显示进度并隐藏旧报告入口，完成后以新报告实例自动打开完整报告；报告记录开始/完成时间与 App 版本。异常结果也替换旧报告，已保存内容仍可在重启后查看。新增报告替换/持久化回归检查，以及原生链接 ZIP、路径/Books 对应关系与元数据错误分类测试。

IPA 校验要求版本 1.3.9 和 `webclip-diagnostics-v4`。构建、测试与实机结果需分别记录。

## 同步清单与分步搬运（1.3.8）

目录诊断和 WebClip 文件夹安装会核验 `Params.AssetManifest.Book`：每个预期 AssetID 必须存在且 IsDownload 为 true（或数值 1）。仅收到名为 AssetManifest 的消息不再允许继续搬运。
目录诊断在清单未接纳时仍生成报告并执行暂存清理，不发送 FileComplete。报告中的 manifestAudit 只记录预期条目的匹配结果，不导出其他 Books 条目的名称或 ID。
链接与载荷分步发送，每一步检查原始暂存源是否已消失；失败就停止后续搬运，不重发写入请求。源文件消失仍不等于目标文件完整落地，成功仍需最终逐字节读回。
新增 failureStage 区分清单未接纳、链接搬运未确认、载荷搬运未确认、最终读回未确认。fileCompleteMessagesSent 记录实际发送数量。
完整报告保留原有清理范围说明。仅有 SyncFinished、源文件移走或编译通过，都不能证明桌面图标可用。请先只运行一次目录诊断。
IPA 校验要求 `webclip-diagnostics-v3`，应用显示版本 1.3.8。

## 原生核心诊断（1.3.7）

本版从 Rust 源码重新构建设备和模拟器框架，不再使用仓库内旧二进制。
IPA 打包检查要求包含 `webclip-diagnostics-v2` 标识，避免只更新界面而没更新核心。
目录验证保留 FileComplete 之后的 ATC 消息，回应 Ping，记录 SyncFailed；读回会保留原始 AFC 错误、实际长度和暂存 payload 是否还在。
只重试读取，不自动重发写入。`cleanupComplete` 仅检查 AFC 暂存区，不涵盖目标目录残留。
这仍是诊断改进，不能将编译通过或消息发送完成等同于实机写入成功。

## 报告导出（1.3.6）

原来直接分享长文本的入口已替换为独立报告页。点击「查看、复制或保存完整报告」，
可以复制全文后返回聊天粘贴，也可以通过系统文件导出器保存 UTF-8 TXT。
报告页显示完整内容，不受预览 180 字限制，也不依赖 VPN 或设备配对。
覆盖更新并保持相同签名 Bundle ID 可继续读取已有本地记录；不要删除旧 App 后重装。

## 重启后没有图标

已收到 27.0.1 上「接口成功，重启后仍无书签」的实测反馈，功能仍未成立。
GoldenNugget 的对应功能通过 HomeDomain 恢复流程投放，不能用它的成功案例证明本分支 AirLift 传输可行。
当前 AirLift 文件夹接口不读回验证目标目录，不能判断目录实际落地或被 SpringBoard 识别。
本版保留每次 AirLift 回调日志；在「写入记录 → 排查信息」查看或手动导出。先查看既有操作日志，不要连续尝试写入。
新增「目录诊断」调用上游 canary 接口：仅对固定 WebClips 目录创建随机测试文件，读回核对 exactBytesRecovered，并单独报告 cleanupComplete。它能验证目录字节往返，不能证明 Info.plist/icon.png 实际落地或已注册。只有用户明确点击验证才执行。
后续仍需确认可用的书签投放／注册路径，才能宣布实机功能可用。

## 连接超时（1.3.4）

`Device connection failed` 表示核心库在打开文件服务和写入之前未能建立隧道。
末尾 `172.16.0.1` 是备用候选地址，不是检测到的 Wi-Fi 地址；完整原因需结合日志和 VPN 配置判断。
页面现在检查目标地址的隧道路由，不再仅凭存在任意 VPN 接口打绿勾；绿勾仍不代表设备服务已验证。
只有明确发生在写入前的连接错误才允许手动重试；未知错误和可能部分写入的错误继续锁定重复操作。
原始错误保存在记录中。此版本改善检测、提示和重试，不保证修复 VPN 配置或设备配对故障。

## 首次测试

1. 先制作完整设备备份，确保照片和重要聊天记录另有可用副本。
2. 打开“图标主题”，输入已安装 App 的真实 Bundle ID、桌面名称并选择图片。
   微信官方包通常为 `com.tencent.xin`；自签包以实际 Bundle ID 为准。
3. 预览后新增一个图标，保持应用在前台。不要同时操作钱包、壁纸或密码主题。
4. 返回成功仅表示 AirLift 接口完成，不代表文件已读回验证、图标已注册或 App 启动正常。
5. 选择“刷新桌面”或手动重启手机，然后检查：图标显示、目标 App 启动、快捷指令提示、重启后保留。
6. 尝试长按新增图标删除书签；不要删除原 App。若不显示或不能删除，保留写入记录，不要连续重试。

## 实现范围

- 在本机生成 `Info.plist` 和标准化的 180×180 PNG。
- 使用直接关联已安装应用的 `ApplicationBundleIdentifier`，不生成 URL 或快捷指令。
- 调用上游 `al_exploit_inject_folder`，固定写入 `/var/mobile/Library/WebClips/` 下新建的随机 UUID 文件夹。
- 不接受任意路径、不覆盖旧书签、不编辑桌面布局数据库、不调用备份恢复或抹机流程。
- 上游 AirLift 传输仍会使用临时 Media/Books 同步文件，不能将其称为“完全不改其他文件”或零风险。
- 写入前持久化操作记录，失败不自动重试，刷新桌面需要单独操作。
- 第一个版本不提供 App 自动枚举、批量导入、原位更新或系统文件删除。

## 构建

默认 push 和手动构建只生成设备核心和未签名 IPA，不编译模拟器或运行 UI 测试。需要界面/报告回归时，在手动 Actions 中开启 `run_ui_tests`。本地 `AIRLIFT_BUILD_SIMULATOR=0 bash build-ios.sh` 可仅生成设备框架；不设置时保留设备与模拟器双框架行为。

GitHub Actions 在 macOS 上运行 XcodeGen，检查 payload/path/version gate，然后编译设备版 IPA。
不需要开发者证书或仓库 secrets。不要把证书、密码或配对文件加入工作流。

本地 macOS：

```sh
brew install xcodegen
xcodegen generate
swiftc ios-app/WebClipSpec.swift ios-app/NetworkStatus.swift scripts/check-webclip.swift -o /tmp/check-webclip
/tmp/check-webclip
bash build-ipa.sh Release
```

图标关联机制参考 GoldenNugget / Cowabunga 的 WebClip 格式。
本分支独立实现 Swift payload 生成和界面，复用 AirCard 原有 AirLift 库。
